# Preprocessing — step-by-step description

**What this document is.** A complete, ordered description of every operation applied to
the imaging data between the released BreastDCEDL volumes and the tensor that reaches the
network. Each step states *what* is done, *why*, and — where one exists — the
*measurement* that decided it.

**Companion figures**, in `docs/preprocessing_figures/` (`.png` and `.pdf`), all
regenerated by `scripts/build_preprocessing_walkthrough.py`:

| figure | shows |
|---|---|
| `fig_p1_walkthrough` | the same slice at every step, left to right |
| `fig_p2_normalisation` | normalisation scope: whole volume (ours) vs per slice (the authors') |
| `fig_p3_slice_selection` | which slices are kept, and which are discarded |
| `fig_p4_load_time` | what is applied every epoch, at load time |
| `fig_p5_flowchart` | the pipeline as a diagram |

None of these figures is illustrative. Each panel is produced by calling the same
functions `core/dataset_builder.py` calls, in the same order, with the parameters read
from the dataset's own `config.json`. The final panel of `fig_p1` is the PNG read back
from disk — the actual file the network trains on.

**Marker convention**, carried over from `DATASET_REPORT.md`:

| marker | meaning |
|---|---|
| *(unmarked)* | verified against a file in this repository |
| **[PAPER]** | reported by an external publication, cited |
| **[MEASURED]** | a conclusion from our own experiments, with the measurement |
| **[UNCONFIRMED]** | defensible on general grounds, not supported by a measurement of ours |

## 0. Inputs, outputs, and what "raw" honestly means

| | |
|---|---|
| **input** | BreastDCEDL **MinCrop** release (Zenodo record 18114231): 3-D NIfTI volumes, cohorts I-SPY2 + I-SPY1 + Duke |
| **output** | `data/multi_subtype_80mm/` — 2,063 patients, 16,378 images, 224×224 8-bit RGB PNG |
| **code** | `core/dataset_builder.py` (common machinery) + `pipelines/thesis/preprocessing.py` (the three pipeline-specific functions) |
| **driver** | `notebooks/03_build_dataset_mine.ipynb` |

**"Raw" in this project means raw relative to us, not raw from the scanner.** The
released volumes have already been through the dataset authors' own pipeline — DICOM to
NIfTI conversion, and the MinCrop tumour-centred crop to 256×256 in plane with the tumour
z-range padded by two slices each side. That cannot be undone from what this repository
holds; the original DICOM series are not present. Everything below is what *we* add on
top.

**Regenerating MinCrop is explicitly not done.** The Zenodo release *is* the authors'
output. Rebuilding it could only introduce differences from the artefact the published
results were computed on.

---

## 1. Read the three DCE phases

Each patient contributes three separate 3-D NIfTI volumes, one per dynamic
contrast-enhanced acquisition time-point. They are read with `nibabel` as float32 and
stacked into a single array of shape `(3, Z, Y, X)`.

**Which three time-points.** The indices come from the release metadata columns `pre`,
`post_early` and `post_late`. **[PAPER]** This follows the authors' own specification:
time-points 0, 2 and `min(last, 6)` for the I-SPY cohorts, and 0, 1 and the final
acquisition for Duke.

**Fallback rule.** When a requested index is absent for a patient, the **last available
acquisition** is substituted rather than an arbitrary file — which is what the authors
specify for Duke. The index *actually used* is written into the output CSV
(`phase_pre`, `phase_early`, `phase_late`), so no substitution is ever invisible.

**Guard.** If the three phases do not share a shape, the patient is rejected rather than
resampled. Silently resampling one phase onto another would fabricate spatial
correspondence that the acquisition does not guarantee.

---

## 2. Sanitise — non-finite voxels to zero

```python
np.nan_to_num(volume, nan=0.0, posinf=0.0, neginf=0.0)
```

**Why.** A single NaN propagates through the min–max in step 4 and turns the entire
patient into NaN, silently. Zero is the conservative replacement: a non-finite voxel in
this data sits in air, which is background.

**Alternative rejected.** Dropping affected patients would discard whole cases over a
handful of voxels.

---

## 3. Locate the lesion

The two annotation types in this dataset are not the same object, and the whole design of
this step is about not letting that difference become a difference in framing.

**Mask cohorts (I-SPY1, I-SPY2).** A 3-D binary voxel mask ships with the release. It is
reduced to a per-slice tumour area; slices with at least `min_tumor_px = 10` tumour pixels
define the z-extent. The in-plane bounding box is taken from **the single slice with the
largest tumour area** (`roi_basis = "area_max"`).

**Box cohort (Duke).** **[PAPER]** Duke ships no segmentation — only an expert-drawn
bounding box: *"Expert radiologists annotated bounding boxes on planes containing the
largest tumor area"*. The box comes from the metadata columns `sraw / eraw / scol / ecol`.

Its z-extent is **not** taken from `mask_start / mask_end`: those index the *original*
volume, whereas MinCrop is already cropped in z. It is derived from the MinCrop
construction rule — tumour range plus two slices of margin per side — so the tumour
occupies `z ∈ [2, nz−3]`.

**Why the largest-area slice for both, and not the 3-D union for the masks.** Because
that is what the Duke annotation *is*. Using a 3-D union for I-SPY and a single plane for
Duke would introduce a systematic, cohort-specific difference in framing — and given that
a classifier can identify the source cohort at macro-AUC **0.9978**, a cohort-specific
difference is the most expensive error available in this project. The two centring rules
differ by 2.3 mm at the median and up to 25.6 mm in the tail.

**Verification.** Where both a mask and a box exist (I-SPY2), the box construction was
checked against the real masks: **767 of 767 exact matches** for patients whose original
scan was already 256×256. That case covers 914 of the 916 Duke patients.

**Guard.** Patients with `n_xy ≠ 256` are rejected, because the box coordinates do not
map. In this release all 918 Duke rows have `n_xy = 256`, so the guard excluded nobody.

**Duke has no mask, so the crops were verified by physics instead.** Contrast enhancement
(G − R) at the centre of the crop against its periphery:

| cohort | ROI source | centre | periphery | ratio | centre > periphery |
|---|---|---:|---:|---:|---:|
| I-SPY2 | mask | 30.14 | 7.32 | 4.12× | 95% |
| I-SPY1 | mask | 34.97 | 8.84 | 3.96× | 90% |
| **Duke** | **box** | 23.54 | 5.02 | **4.69×** | **96%** |

Duke scores *better* than either mask cohort. The crops contain tumour.

## 4. Intensity normalisation — min–max over the whole 4-D volume

```python
lo, hi = nanmin(volume), nanmax(volume)
volume = clip((volume - lo) / (hi - lo), 0, 1)
```

Applied **once, to the whole 4-D volume — all three phases and all slices jointly — and
before any cropping.**

**[PAPER] What the authors do.** *"All images underwent Min-Max normalization and
conversion to 8-bit format"*, applied **per slice**.

**[OURS] Why the volume instead of the slice.** Per-slice normalisation destroys the
intensity relationship *between* slices and *between* phases. An almost-empty slice is
rescaled to the same brightness as one containing an intensely enhancing lesion, and the
enhancement ratio between pre- and post-contrast — the biological signal a DCE study
exists to capture — is removed. `fig_p2_normalisation` shows this directly: under our
rule each slice keeps its true brightness; under theirs every slice is forced to a maximum
of exactly 1.0.

**Why before cropping, not after.** Normalising first makes the intensity scale a property
of the *patient*. Normalising after would make each image's brightness depend on how much
background the window happened to include.

**A note on reading this step in a figure.** Min–max is an affine rescale. A
"raw versus normalised" image pair would show two identical-looking pictures, because any
float array must be display-windowed to be drawn at all, and that windowing is itself a
min–max. What actually changes the pixels is the *scope* of the statistic. That is why
`fig_p1` reports the numeric range under each panel (`[0, 3626]` → `[0, 1]`), and why
`fig_p2` compares scopes rather than raw against normalised.

**Alternative implemented and rejected — `chanclip`.** `normalize_channel_clip` clips each
phase at its own 98th percentile before scaling. **[PAPER]** This was the *winning*
strategy in the authors' own later seven-way benchmark (arXiv:2510.13897): AUC 0.744
against 0.700 for global min–max, their worst.
**[MEASURED] It lost here**: 0.5830 against 0.6078 on our 3-class task, two seeds, both in
the same direction. Their result was for binary HER2 on their preprocessing; it did not
transfer. Kept available, not default.

## 5. Slice selection — trim 15% off each end, then keep 8 evenly spaced

```python
cut  = floor(len(z_indices) * 0.15)
core = z_indices[cut : len(z_indices) - cut]
keep = core[linspace(0, len(core) - 1, 8)]
```

A patient with fewer than eight slices after the trim keeps all of them — better five
images than a lost patient. The original count is recorded in `n_slices_tumor`, so those
cases can be filtered later without reprocessing.

**Why proportional trimming and not absolute.** A tumour spanning 60 slices loses 9 at
each end; one spanning 8 loses 1. An absolute rule ("drop 3 slices") would erase half of a
small lesion. The trim is purely geometric, which means it behaves identically with a
segmentation mask and with a bounding box — no difference of treatment between cohorts.

**Why spread and not the N central slices.** Neighbouring slices 1–2 mm apart are
near-duplicates: twenty of them contribute twenty near-identical gradients. Spreading
covers the lesion end to end for the same number of images.

**[MEASURED] What the previous behaviour cost.** The old pipeline kept *every*
tumour-bearing slice: a mean of 38 per patient, a maximum of 150, and 21% of them carrying
fewer than 100 tumour pixels. Two harms, both real — the per-patient mean that produces
the final prediction was diluted by near-empty slices, and a patient with 150 slices
contributed 150 gradient samples against another's 8.

**Reduction: 63,460 tumour-bearing slices → 16,378 images (25.8%).**

The resulting distribution: mean 7.94 slices per patient, median 8, range 1–8. Fifty-one
patients have fewer than 8.

## 6. Crop — an 80 mm *physical* window

```python
side_px = max(round(80.0 / xy_spacing), 8)
```

A square window of **80 physical millimetres**, centred on the ROI box centre. Where the
window extends past the image edge the caller **zero-pads** rather than shrinking —
shrinking would change the scale for peripheral tumours only, and constant scale is the
entire point of the step.

### 6.1 Why not resize the tumour to fill the frame

The common choice — a margin expressed as "15–20% of the bounding box" — makes the lesion
fill the frame identically in every patient, and in doing so **erases tumour size**. Two
consequences:

1. **[MEASURED] Tumour size is predictive on this task.** Size alone is worth macro-AUC
   0.58–0.68 here, and it ranks as the most important predictor in the BreastDCEDL
   authors' own feature-importance analysis.
2. **Size is biology.** Tumour extent is part of staging and correlates with subtype, and
   the three cohorts differ roughly five-fold in median tumour volume. An 80 mm frame
   keeps it: a 60 mm tumour occupies nine times the frame area of a 20 mm one, as in
   reality.

### 6.2 Why millimetres and not pixels

`xy_spacing` ranges **0.312 – 1.406 mm/px** across this dataset — a 4.5-fold spread. A
fixed 224-pixel crop would cover 70 mm for one patient and 315 mm for another. The field
of view would then vary systematically by cohort, and the degree of magnification would
itself identify the source.

After the window and the resize, **every image in the dataset sits at 0.35714 mm/px** —
constant across all 16,378 rows.

**[MEASURED] Effect on the resampling factor:** 1.96× (Duke) / 1.91× (I-SPY2) / 2.20×
(I-SPY1) — similar across cohorts, against roughly 4× versus 2× for a proportional crop.

### 6.3 Why 80 mm specifically

It is the smallest window containing the whole tumour for the **median patient of all
three cohorts** (I-SPY1 64.8 mm, I-SPY2 61.2 mm, Duke 29.2 mm), plus about 7 mm of
peritumoral tissue per side. **[PAPER]** That margin sits inside the 4–6 mm band reported
optimal in the peritumoral-radiomics literature, and a separate multi-task study found
tumour-core-only to be the *worst* configuration tested (−4.9%), so peritumoral tissue is
kept deliberately.

The window fully contains the lesion in **81%** of patients.

## 7. 8-bit, resize, and save as RGB PNG

In order:

1. Crop the normalised plane, zero-padding outside the image.
2. `(clip(plane, 0, 1) * 255).astype(uint8)`, transposed to H × W × C.
3. Resize to **224 × 224** with **PIL LANCZOS** — only if the window side is not already 224.
4. Save as an RGB PNG with `optimize=True`.

**Channel assignment: R = pre-contrast, G = early post-contrast, B = late post-contrast.**

**[PAPER]** This is the authors' own fusion, motivated by making ImageNet-pretrained
models usable on natively 4-D data. **Why we kept it:** the three-channel layout is what
makes ImageNet pretraining possible at all, and because the phases are ordered in time,
the *colour* of a voxel encodes its enhancement kinetics — the wash-in and wash-out
behaviour that is the diagnostic content of a DCE study. Greyscale repeated three times
would discard it.

**[MEASURED] Honest note:** measured against replicated greyscale channels, RGB fusion
scored −0.024 macro-AUC. It was **kept anyway**, because it is what makes the channels
meaningful and the difference is inside the noise floor.

**Why 224.** The native input size of the ImageNet-pretrained torchvision backbones, so no
interpolation happens inside the network.

**[UNCONFIRMED] Why LANCZOS.** It is the highest-quality PIL resampling filter for the
direction almost every image travels (upsampling). We did **not** benchmark it against
bilinear or bicubic.

## 8. Splitting — by patient, taken from the release

The split comes from the **`split` column of the BreastDCEDL MinCrop metadata**
(`0 = train, 1 = test, 2 = val`). It is not re-derived, so it is identical to what the
dataset authors published for this subset.

**Every slice of a patient is in exactly one split.** Splitting by slice would let a model
recognise the *patient* rather than the disease — the original leak in this project's
first phase, and now a hard rule enforced by a verification step that refuses to pass.

| split | patients | images | trivial baseline |
|---|---:|---:|---:|
| train | 1,527 | 12,131 | — |
| validation | 268 | 2,132 | 0.4925 |
| test | 268 | 2,115 | **0.5112** |

Note that this is **not** the 1,099/177/176 partition described in the BreastDCEDL paper.
That one is defined over the **pCR-labelled** subset; ours covers the **subtype-labelled**
subset. Same column, different subset.

## 9. Load time — what is applied every epoch

**The PNG on disk is never fed to the network unchanged.** The files are unaugmented; the
following runs at load time, on the **training split only** (`fig_p4_load_time`):

```
/255 → [0,1]  →  augmentation  →  ImageNet mean/std normalisation  →  model
```

Augmentation profile `default`, from `core/data.py::AugmentConfig`:

| transform | probability | parameters |
|---|---:|---|
| horizontal flip | 0.50 | plausible as the contralateral breast |
| **vertical flip** | **0.00** | a cranio-caudal flip produces anatomy that does not exist |
| rotation | 1.00 | ±15° |
| zoom / scale | 1.00 | 0.9 – 1.1 |
| translation | 1.00 | ±8% |
| brightness | 1.00 | ×U(0.8, 1.2), clamped |
| gaussian noise | 0.25 | σ ~ U(0.005, 0.03), clamped |
| cutout | 0.00 | disabled |

Rotation, zoom and translation are drawn independently but composed into **one** affine
transform, so the image is interpolated once rather than three times.

**The order is deliberate: ImageNet normalisation is LAST.** Brightness and noise operate
in `[0, 1]` space, where they remain interpretable as physical quantities. After ImageNet
normalisation they would not be.

**Deliberately absent:** MixUp/CutMix at image level (they blend lesions from different
patients, and the diagnostic signal here is small, local and low-contrast); strong elastic
deformation (it alters tumour morphology, which is precisely the feature being
classified). `mixup_alpha = 0.0`.

**[MEASURED] The augmentation is the only regulariser with a measured effect.** Halving it
(profile `half`, same amplitudes at half probability) was the single clearest overfitting
result in the project:

| | default | half |
|---|---:|---:|
| training accuracy | 0.57 | **0.99** |
| train − test gap | 0.135 | **0.512** |
| test macro-AUC | — | **−0.040** |

**The current augmentation is what holds this model back from memorising.**

## 10. What was deliberately not done

Stated so their absence is not mistaken for oversight.

| not done | why |
|---|---|
| bias-field / N4 correction | the release is already standardised |
| skull / chest-wall stripping, breast segmentation | the 80 mm tumour-centred window makes it largely unnecessary |
| registration between phases | assumed co-registered as released; only their shapes are verified |
| z-resampling | slice thickness is left as acquired; only the in-plane scale is harmonised |
| background masked out | **[PAPER]** the literature reports tumour-core-only as the worst configuration (−4.9%), and it is impossible for Duke, which has no mask |
| **inter-cohort intensity harmonisation (ComBat)** | **a real limitation.** Given a source probe of 0.9978, this is a clear candidate for future work |
| regenerating MinCrop | the Zenodo release *is* the authors' output |

## 11. Interventions measured and rejected

Every row is a real experiment on this data, not a literature claim.

| intervention | Δ macro-AUC | verdict |
|---|---:|---|
| `chanclip` (per-channel q0.98) | −0.025, both seeds same direction | rejected — despite winning the authors' own benchmark |
| `pclip` (p0.5/p99.5 global) | −0.034, lost on all 3 seeds | rejected |
| subtraction + per-patient z-score | −0.021 | rejected |
| per-slice normalisation (the authors' rule) | see §4 | rejected on mechanism |
| balanced sampling | −0.027 | rejected |
| label-noise filter (bbox ≥ 100 px²) | −0.032 | rejected |
| joint 3-phase normalisation | −0.004 | no effect |
| tight tumour crop (4 mm margin) | +0.015 (inside noise) | rejected |
| 6 mm vs 4 mm margin | −0.021 | rejected |
| proportional crop (bbox + %) | lost to no crop at all | rejected — it erases tumour size |
| 2.5D frame stacking (3 / 9 channels) | −0.015 / −0.014 | rejected |
| 3D volumes (96³) | 0.53–0.58 | rejected |
| multi-task decomposition (3 binary heads + CBAM) | hurt TripleNeg by 0.040 | rejected |
| halving augmentation | −0.040, gap tripled | rejected |
| RGB phase fusion vs replicated greyscale | −0.024 | **kept anyway** — it makes the channels meaningful |

**The conclusion of the whole preprocessing programme.** Seven literature-grounded
interventions, all null or negative, everything landing between 0.59 and 0.65 macro-AUC.
That is not a run of bad luck — it is the result: **the ceiling is in the data.** A
106-study, 12,989-patient systematic review concludes conventional quantitative MRI
features *"might play a limited role"* in subtype prediction, and Zhang et al. report
0.79/0.91 within-centre collapsing to 0.52/0.44 **cross-centre**, which is exactly the
line our numbers sit on.

## 12. The honest caveat on the redesign

On the **same 99 I-SPY2 test patients**, this preprocessing scored **0.5837 ± 0.011**
against **0.6201 ± 0.024** for the older pipeline. The difference is inside the 0.067
macro-AUC noise floor, so the verdict is *"no difference detected"* — but it is **not** the
improvement that was expected, and that must be stated wherever the redesign is described.

What it did buy:

* a validation-to-test gap of **+0.015** against **+0.073** for the pooled runs — a result
  that generalises more honestly;
* much more even per-class recall, `[0.60, 0.50, 0.37]`;
* a constant pixel spacing, which removes the resolution signature a fixed-pixel crop
  would encode.

## 17. How to regenerate

```bash
cd src
python3 scripts/build_preprocessing_walkthrough.py
python3 scripts/build_preprocessing_walkthrough.py --pid ISPY2-243836
```

Any patient in the dataset works. The default is `ISPY2-111881` — a mask cohort, so the
lesion contour can be drawn rather than asserted. Pass a Duke patient to see the
bounding-box case.

**Known open defect.** `config.py::COHORT_DIRS` points at `BreastDCEDL/`, which holds the
metadata CSV but **not** the imaging volumes — those are under `raw_dataset_BreastDCEDL/`.
The dataset was built when the volumes were reachable at the configured path; they are not
reachable there today. Both figure scripts resolve the fallback themselves, so figures
regenerate, but **the builder's configured path is stale and would fail today.** This is
recorded rather than silently patched: a path that no longer resolves is a reproducibility
defect, not a cosmetic one.
